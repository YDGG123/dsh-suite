# 测试与反向验证（TESTING）

> **只跑绿不算证明。** 安装/校验/回滚这类"闸门"必须证明**该红的时候真的红**，
> 否则它只是把所有东西都放过去的橡皮图章。本文记录反向场景、期望退出码与实测结果。

## 怎么跑

```bash
bash scripts/selftest.sh          # macOS / Linux（会自建临时 HOME 沙箱，不碰你真实 profile）
```

- 退出码：`0` = 所有反向场景都按预期表现（**这是通过**）；非 0 = 有场景没红、红了但码不对，或结构断言（文件/字节/文本）不符。
- 脚本会在 `mktemp -d` 的临时目录里造一个假 profile，跑完自动清理，**不影响真实 DSH 数据**。
- R16–R19 跑在临时仓库副本里（脚本/文档/manifest/app 各拷一份），**不改本仓库的任何文件**。
- R1–R6、R11 是"必须红"的场景；R7–R15（含 R12b）是"正确实现下应当绿、写错就会红"的闸门（撤错插件、删多、误删用户配置、丢 had 目录、非幂等都会让它们变红）。

## 反向场景与期望退出码

| 编号 | 场景 | 怎么做坏的 | 期望退出码 | 说明 |
|---|---|---|---|---|
| R1 | **装错目录** | `--dsh-home` 指向不存在的路径 | **1** | 预检失败：找不到 DSH 数据目录 |
| R2 | **仓库不完整** | 临时藏起 `plugins/dsh-plugin-mobile-gateway/lib/index.mjs` | **1** | 预检失败：仓库缺构建产物（提示重新下载） |
| R3 | **半装** | 安装后删掉一个关键文件 | **3** | 校验失败：文件齐全性/哈希不符 |
| R4 | **哈希不符** | 改动已安装文件的一个字节 | **3** | 校验失败：内容与仓库不一致 |
| R5 | **无备份回滚** | 在空 profile 上回滚 | **4** | 拒绝执行：没有备份可回滚 |
| R6 | **无备份单插件回滚** | 空 profile 上 `--only-gateway` | **4** | 同样拒绝：单插件也要有备份与 state.txt |
| R7 | **只撤网关** | 装两个后 `--only-gateway` | **0** | ds-bot 目录**逐字节未动**、登记保留、`--only-dsbot --verify-only` 仍绿 |
| R8 | **单插件回滚幂等** | 上一步再跑一次 | **0** | 打印"已处于回滚状态"，不误删 ds-bot，校验仍绿 |
| R9 | **只撤 ds-bot** | 装两个后 `--only-dsbot` | **0** | 网关目录逐字节未动、7 个依赖与 cordis 块仍在、`--only-gateway --verify-only` 仍绿 |
| R10 | **整份回滚不受影响** | 装两个后整份回滚 | **0** | `package.json` / `cordis.patch.yml` 与备份**逐字节一致**，两个插件目录都撤 |
| R11 | **参数互斥** | 同时给 `--only-gateway --only-dsbot` | **4** | 参数非法 |
| R12 | **用户自己的配置块** | profile 里已有手写的 `- id: mobile-gateway` 块（没有 dsh-suite 注释），再只撤网关 | **0** | 该块**逐字节保留**——收窄后只认安装写的注释行，误删就红 |
| R13 | **重装后再单撤（升级）** | 连续装两次，再 `--only-gateway` | **0** | 第二次安装属 `had:`：目录、运行依赖、原有的配置块都保留，只还原登记——回到"第二次安装前" |
| R12b | **用户块紧跟安装块** | 安装块之后**直接**追加一个用户自己的 `- id: mobile-gateway` 块，再 `--only-gateway` | **0** | 跳过区间只认我们块首的那一个 `- id:`；用户块必须留下（吞掉就红） |
| R14 | **had: 目录保留** | 安装前就存在 `node_modules/ds-bot`（登记 `0.2.0`），再 `--only-dsbot` | **0** | 备份没有旧版本：**保留当前目录**，登记还原成安装前的 `0.2.0`，并明确提示 |
| R15 | **整份回滚同样保留 had** | 安装前就存在网关目录，再整份回滚 | **0** | had 的目录与它的运行依赖都保留；`new:` 的另一个插件仍撤掉 |
| R16 | **文档与包一致** | 临时副本上跑 `sync-from-dev.sh --check-docs`，再改坏 README 里的 sha | **0 / 1** | 只读自检：一致 → 0；文档被改动 → 1 并指名缺哪个值 |
| R17 | **漏传 --ipa** | `sync-from-dev.sh --dsbot <目录>`（不给 `--ipa`、不给 `--no-ipa`） | **2** | 参数非法：不许静默沿用旧 sha256 |
| R18 | **相对路径锚点** | 从别的 cwd 用相对路径 `--gateway gwsrc --no-ipa` | **0** | 按调用者 cwd 解析并成功同步；源目录里的 `dev/`、`test/` 不进发布树 |
| R19 | **换包后文档自动改写** | 临时副本上用一个新 IPA 同步 | **0** | README/INSTALL 的 8 处自动更新、旧名/旧 sha 0 命中、随后 `--check-docs` 通过 |

安装脚本 `install.sh` / `install.ps1` 的退出码约定（两者一致）：

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 预检失败（环境/仓库不完整） |
| 2 | 安装/复制失败（含复制运行依赖失败） |
| 3 | 校验失败（文件不全、哈希不符、依赖缺失） |
| 4 | 环境不支持 / 参数非法 / 无备份可回滚 |

## Windows（`install.ps1` / `rollback.ps1`）的覆盖范围

**当前没有 Windows 反向测试**（维护机是 macOS，无 PowerShell 运行时）。现有的保障是：

- **静态检查**：`install.ps1` / `rollback.ps1` 的括号/引号/块注释/here-string 全部配平
  （2026-10-25 对重写后的 `rollback.ps1` 复跑：`() {} []` 全配平、字符串与块注释都闭合，exit 0）
- **参数与分支审阅**：`param(...)` 块、`Die <码> "..."` 的退出码分支与上表一致
  （`1` 预检、`2` 复制、`3` 校验、`4` 参数/环境）
- **单插件回滚的 PowerShell 实现**与 `rollback.sh` 同规则：只认安装写的 `# dsh-suite:` 注释行、
  `state.txt` 只读、幂等、依赖只随网关撤。**但本轮没有 Windows 实机验证**，上表的 R6–R15（含 R12b）只算
  "静态通过"，不计入实测。

**待补**：在 Windows 上跑一遍等价的反向场景（装错目录 / 仓库不完整 / 半装 / 哈希不符 / 无备份回滚 /
只撤网关后 ds-bot 校验仍绿 / 幂等重跑 / 用户自己的配置块不被误删），把实测退出码补进本文。
**在那之前，Windows 路径的结论只能是"静态通过"，不是"实测通过"。**

## 维护规则

1. **新增一项检查，就新增一条反向场景**——否则这项检查等于没写。
2. 退出码是**对外契约**（`docs/INSTALL.md` 里引用），改动需同步文档。
3. 反向场景里的"做坏"方式要尽量贴近真实事故：装错目录、半装、被改过的文件、缺备份。
4. 失败输出要能指导下一步（脚本里的报错都带"怎么办"），别只说"失败了"。
5. 维护者同步脚本的改动同样要过这里的闸门：文档与包一致（R16）、参数必须显式（R17）、
   路径锚点是调用者 cwd（R18）、换包后文档自动改写（R19）——这四条都是"改坏了才看得出"的。
